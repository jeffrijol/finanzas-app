Objetivo:
Rediseñar el modelo de datos actual de Supabase para implementar un sistema de organizaciones, 
miembros y roles (similar a Clerk Organizations: https://clerk.com/organizations), 
manteniendo la compatibilidad con las tablas existentes.

Contexto actual:

    Tablas principales: ExcelUpload, Item, ItemType, Transaction, TransactionCategory

    Relación actual: varias tablas usan userId para vincular datos a un usuario individual

    Autenticación actual: basada en usuario único (Supabase auth.users)

Requerimientos nuevos:

    Organizaciones: cada organización tendrá su propio conjunto de datos 
    (items, transacciones, categorías, etc.).

    Miembros: los usuarios (auth.users) pueden pertenecer a una o más organizaciones como miembros.

    Roles: dos roles básicos:

        admin: CRUD completo en los datos de la organización

        viewer: solo lectura

    Políticas RLS: usar Row Level Security de Supabase para restringir acceso por organización y rol.

    Migración: mantener datos existentes asignándolos a una organización llamada "Avance" y asociando usuarios actuales como admin.

Propuesta de tablas nuevas:

    Organization: id, nombre, created_at, primary_contact_user_id (opcional)

    Member: id, user_id (referencia a auth.users), organization_id, role_id, joined_at

    Role: id, name (admin/viewer), permisos (array o texto)

Cambios en tablas existentes:

    Agregar organization_id a: Item, Transaction, TransactionCategory, ExcelUpload

    Remplazar userId por member_id

    Ajustar claves foráneas y RLS

Puntos clave a considerar:

    Cómo manejar usuarios que pertenecen a múltiples organizaciones (selector de org en UI)

    Cómo migrar datos existentes sin pérdida

    Cómo integrar con Supabase Auth (tabla profiles solo si es necesario)

Salida esperada:

    Scripts SQL para nuevas tablas y modificaciones

    Políticas RLS por tabla y rol

    Script de migración de datos existentes

    Recomendaciones para la capa de aplicación (API, hooks, UI)
