Proyecto: finanzas-app • Desarrollador único • Commits pequeños en develop • Merge infrecuente a master
📋 Estrategia Recomendada

Usar Antigravity Workflows para CI/CD y GitHub Branch Protection Rules para seguridad, con configuración mínima pero efectiva.
🔧 Parte 1: GitHub Branch Protection Rules (YAML para Antigravity)

plan:
  title: "Configurar protección de rama master en GitHub"
  description: "Proteger rama master con reglas básicas pero efectivas para desarrollador único"
  steps:
    - step: "Acceder a configuración de ramas"
      action: "navegar"
      target: "https://github.com/jeffrijol/finanzas-app/settings/branches"
    
    - step: "Añadir regla de protección"
      action: "configurar"
      config:
        branch_name_pattern: "master"
        rules:
          - "Require a pull request before merging"
            settings:
              required_approving_reviews: 0  # Como eres solo tú
              dismiss_stale_reviews: false
          - "Require status checks to pass before merging"
            status_checks:
              - "ci-build-and-test"
              - "lint-check"
          - "Require branches to be up to date before merging"
          - "Include administrators": true  # Tú mismo puedes override si es necesario
    
    - step: "Configurar reglas adicionales"
      action: "explicar"
      content: |
        Opcional pero recomendado:
        - "Restrict who can push to matching branches": NO activar (eres solo tú)
        - "Allow force pushes": Desactivar
        - "Allow deletions": Desactivar

🚀 Parte 2: Workflow de CI/CD (YAML para GitHub Actions via Antigravity)

plan:
  title: "Implementar CI/CD básico con GitHub Actions"
  description: "Workflow que valida builds, tests y lint en cada PR a master"
  files:
    - path: ".github/workflows/ci.yml"
      content: |
        name: CI Build and Test
        
        on:
          pull_request:
            branches: [ master ]
          push:
            branches: [ master ]
        
        jobs:
          build-and-test:
            runs-on: ubuntu-latest
            
            steps:
            - name: Checkout repository
              uses: actions/checkout@v4
            
            - name: Setup Node.js
              uses: actions/setup-node@v4
              with:
                node-version: '20'
                cache: 'pnpm'
            
            - name: Install pnpm
              uses: pnpm/action-setup@v2
              with:
                version: 8
            
            - name: Install dependencies
              run: pnpm install
            
            - name: Run linting
              run: pnpm run lint
              continue-on-error: true  # Temporal por errores TypeScript existentes
            
            - name: Build all packages
              run: pnpm run build
            
            - name: Run tests (si existen)
              run: |
                if [ -f "package.json" ] && grep -q '"test"' package.json; then
                  pnpm run test
                else
                  echo "No tests configured"
                fi
            
            - name: Type check (backend only - temporal)
              run: |
                cd packages/backend
                pnpm exec tsc --noEmit

🤖 Parte 3: Configuración de Antigravity Agent-Skills

plan:
  title: "Configurar habilidades del agente para el proyecto"
  description: "Skills específicas para manejar el flujo de desarrollo finanzas-app"
  agent_skills:
    - skill: "auto-review-pr"
      config:
        enabled: true
        rules:
          - "Verificar que PR apunta a master"
          - "Verificar que título sigue convención: feat|fix|chore|docs|style|refactor|test"
          - "Ejecutar validación local antes de aprobar"
    
    - skill: "commit-message-linter"
      config:
        pattern: "^(feat|fix|chore|docs|style|refactor|test)(\\([a-z]+\\))?: .{10,72}$"
        examples:
          - "feat(frontend): añadir gráficos de análisis trimestral"
          - "fix(backend): corregir filtro de fecha en analytics"
    
    - skill: "pr-template"
      config:
        template_file: ".github/pull_request_template.md"
        content: |
          ## Descripción de cambios
          
          ### Tipo de cambio
          - [ ] Nueva funcionalidad (feat)
          - [ ] Corrección de bug (fix)
          - [ ] Refactorización (refactor)
          - [ ] Documentación (docs)
          - [ ] Otro (especificar)
          
          ### Cambios realizados
          
          ### Checklist
          - [ ] El código sigue las guías de estilo
          - [ ] Se han ejecutado los tests localmente
          - [ ] Se ha verificado el build
          - [ ] Documentación actualizada si es necesario

📊 Parte 4: Workflow de Merge Automatizado (Opcional)

plan:
  title: "Workflow de merge semi-automático para desarrollador único"
  description: "Permite mergear a master tras verificación automática"
  workflow:
    name: "Auto-merge after checks"
    trigger: "pull_request.closed"
    conditions:
      - "pr.base_ref == 'master'"
      - "pr.merged == true"
      - "all_checks_passed == true"
    
    actions:
      - name: "Tag version"
        run: |
          # Incrementar versión patch automáticamente
          npm version patch --no-git-tag-version
          git add package.json
          git commit -m "chore: bump version"
          git push origin master
      
      - name: "Create release notes"
        run: |
          gh release create v$(node -p "require('./package.json').version") \
            --title "Release v$(node -p "require('./package.json').version")" \
            --notes-file CHANGELOG.md
